# DBD 下钩计时助手

黎明杀机（Dead by Daylight）杀手端辅助计时器：当人类被救下钩时，自动/手动开始 60 秒正计时，用**颜色告诉你当前处于哪个保护窗口**，悬浮在游戏画面上方。

> ⚠️ **使用须知（请务必阅读）**
> - 本工具**只截取你自己的屏幕画面做识别，不读取/写入游戏内存、不注入、不修改任何文件**，因此不会被 Easy Anti-Cheat 检测为注入类外挂。
> - 但“自动识别下钩并计时”会给杀手提供游戏**故意隐藏的信息**（本应只由人类玩家看到）。这属于**公平性灰色地带**，请仅在了解游戏机制、自用学习的前提下使用，并由你自行承担账号风险。介意者请只用“手动鼠标侧键”模式（相当于普通秒表）。
> - 仅建议在**无边框窗口**模式下运行 DBD（本工具就是为它设计的）。

## 颜色含义（正计时 0 → 60）

| 数字颜色 | 阶段 | 含义 |
|---|---|---|
| 🟡 黄色 | 0 ~ 10 秒 | **下钩保护**（耐力+加速）生效中 |
| ⚪ 白色 | 10 ~ 60 秒 | 只剩**果断反击(DS)** 可用 |
| 消失 | 数到 60 | 效果过期 + 两声提示音 |

## 安装（一次性）

```powershell
cd "d:\Codes\DBD Timer"
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 运行

```powershell
# 正常使用（自动识别 + 鼠标侧键手动兜底）
.\.venv\Scripts\python.exe app.py

# 校准头像框（首次使用前建议做一次）
.\.venv\Scripts\python.exe app.py --calibrate

# 无需游戏，演示悬浮窗效果
.\.venv\Scripts\python.exe app.py --demo

# 开启调试：把识别画面(带状态标注)存到 debug/ 目录，便于排查
.\.venv\Scripts\python.exe app.py --debug
```

也可以在资源管理器里**双击** `启动计时助手.bat` / `校准.bat`。

## 快捷键与悬浮窗

| 按键 | 作用 |
|---|---|
| 鼠标**侧键** `XBUTTON2`(默认) | 手动开始一次 60s 计时（作为自动识别的兜底）。**改键**：点悬浮窗左上角的「键」按钮，按一下你想要的键即可，会自动写入 `config.json`，无需手改文件 |
| `Ctrl+Alt+L` | 悬浮窗 **锁定/解锁**（也可直接点右上角锁按钮） |
| `Ctrl+Alt+Q` | 退出程序 |

- 悬浮窗**解锁态**下可按住任意位置自由拖动；点右上角 **🔓/🔒** 或按 `Ctrl+Alt+L` 锁定。
- **锁定 = 固定位置、禁止拖动**，鼠标仍能点锁按钮，**无需快捷键即可解锁**。
- 位置会在拖动结束/锁定时自动写入 `config.json`，下次启动回到原位。
- 若你希望锁定后连鼠标也"穿透"不挡游戏点击，可在 `config.json` 把 `overlay.passthrough_on_lock` 设为 `true`（此模式下锁定后只能用 `Ctrl+Alt+L` 解锁）。
- 最多 **2 个槽**并行计时（第 3 个及以上事件自动忽略）。

## 校准（推荐，提升自动识别准确率）

`app.py --calibrate` 打开校准窗口，画面上是 DBD 实况（底部 HUD）：

1. **框选 4 个头像**：用鼠标在底部 4 个幸存者头像上各拖一个框（最多 4 个，多画顶掉最早）。
2. **先给每个框拍【记为正常】**：点中某个框（变红）→ 点【记为正常】（保存该槽位的"正常"基线，程序用它与后续状态图做差，从而**去掉角色脸和地图背景、只留下状态图标**）。
3. **出现状态时拍【记为上钩 / 记为倒地】**：等有人**上钩**时，点中该框 →【记为上钩】；有人**倒地**时，点中该框 →【记为倒地】。多拍几张更稳。

   | 按钮 | 何时按 | 存的内容 | 作用 |
   |---|---|---|---|
   | 记为正常 | 该框是正常走动状态 | 该槽原图（每槽一张基线） | 作为"减数"，把脸/背景减掉 |
   | **记为上钩** | 该框里的人正挂在钩上 | **差异图**(状态图−正常图) | 让程序认得"上钩图标"→ 上钩→恢复 才触发计时 |
   | **记为倒地** | 该框里的人正倒地(濒死) | **差异图**(状态图−正常图) | 让程序认得"倒地图标"→ 倒地→恢复 不会误触发 |

   - 建议在**自定对局（机器人局）**里操作：开局的健康机器人正好用来逐个拍"正常"；挂上一台拍"上钩"；砍倒一台(别挂)拍"倒地"。
   - 画面可 **“暂停/继续”** 方便精确指认。
4. 点 **“保存并退出”**。

校准结果存于 `config.json`（归一化坐标）与 `templates/`：`alive/`(每槽正常基线) + `hooked_diff/`、`downed_diff/`(差异模板)。**模板在程序启动时加载**，校准后需**重启** `启动计时助手.bat` 才会生效（日志出现 `hooked模板N张/downed模板M张` 即成功）。

> 没做模板校准也能用：此时走 `simple` 模式，**任何“偏离→恢复”都当作下钩**，代价是“倒地后被人拉起/自起”会误触发一次计时。做完 正常+上钩/倒地 模板后，倒地恢复不会再误触发。

## 检测原理与已知局限

- 每个头像槽维护一张**自适应“正常存活参考”**（跟随该角色外观缓慢学习，无需为每个角色单独拍照）。
- 槽位画面长期偏离参考 => 认为进入某种状态；分类"上钩 vs 倒地"时用**差异图**（当前图 − 该槽正常图）比对模板：差异图已去掉静止的脸与地图背景，只保留状态图标，可跨角色/跨地图复用。
- 被识别为“倒地”后恢复（倒地拉起/自起）**不**计时；其余偏离（上钩、或模板未完全认出的变化）恢复到正常即判定为一次被救下钩并计时（**宁可多报、不漏报**）。
- 三挂牺牲（死亡）不会恢复到“正常”，因此**不会**误触发。
- 已知局限（已尽量在代码/文档里交代）：
  1. 本机无法直接验证 DBD 像素，**默认无框**，务必先校准；
  2. 若程序启动时对方**已经挂在钩上/已倒地**，可能漏掉或需等自动重设基线；
  3. 没拍模板时(简单模式)倒地拉起会误报；拍了 上钩/倒地 差异模板则不会；
  4. 多显示器时目前按**主显示器/窗口所在区域**抓取，若有异常把 DBD 放主屏跑。
- 排查：`--debug` 运行一段时间后把 `debug/dbg_*.png` 发给我即可针对性调参（阈值在 `config.json` 的 `detect` 段）。

## 目录结构

```
app.py                  入口（--demo/--calibrate/--debug）
requirements.txt        依赖
config.json             运行时生成的配置（框、热键、显示设置）
templates/              校准拍的 正常/上钩/倒地 模板
debug/                  调试帧
dbdtimer/
  config.py             配置读写
  timers.py             双槽 60s 计时内核
  overlay.py            透明悬浮窗（拖动/锁/黄白数字）
  gamewindow.py         定位 DBD 窗口
  capture.py            截屏（dxcam -> mss 降级）
  detector.py           状态机识别“下钩”
  hotkey.py             全局热键
  calibration.py        校准界面
```

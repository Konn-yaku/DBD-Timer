# DBD 下钩计时助手

黎明杀机（Dead by Daylight）杀手端辅助计时器：当人类被救下钩时，自动/手动开始 60 秒正计时，用**颜色告诉你当前处于哪个保护窗口**，悬浮在游戏画面上方。

> ⚠️ **使用须知（请务必阅读）**
> - 本工具**只截取你自己的屏幕画面做识别，不读取/写入游戏内存、不注入、不修改任何文件**，因此不会被 Easy Anti-Cheat 检测为注入类外挂。
> - 但“自动识别下钩并计时”会给杀手提供游戏**故意隐藏的信息**（本应只由人类玩家看到）。这属于**公平性灰色地带**，请仅在了解游戏机制、自用学习的前提下使用，并由你自行承担账号风险。介意者请只用“手动鼠标侧键”模式（相当于普通秒表）。
> - 仅建议在**无边框窗口**模式下运行 DBD（本工具就是为它设计的）。

## 颜色含义（正计时 0 → 60，保留一位小数）

**4 行计时器与 4 名逃生者一一对应**（自动识别时：槽0~3 被下钩 → 计时器1~4 各自启动，互不抢占）。数字从 0 正数到 60，显示一位小数（如 `12.3`）。

| 数字颜色 | 阶段 | 含义 |
|---|---|---|
| 🟡 黄色 | 0 ~ 10 秒 | **下钩保护**（耐力+加速）生效中 |
| ⚪ 白色 | 10 ~ 60 秒 | 只剩**果断反击(DS)** 可用 |
| 消失 | 数到 60 | 效果过期 + 两声提示音 |

## 安装（一次性）

```powershell
cd "d:\Codes\DBD Timer"
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 运行

```powershell
# 正常使用（自动识别 + 鼠标侧键手动兜底）
.\.venv\Scripts\python.exe app.py

# 校准头像框（首次使用前建议做一次）
.\.venv\Scripts\python.exe app.py --calibrate

# 无需游戏，演示悬浮窗效果
.\.venv\Scripts\python.exe app.py --demo

# 开启调试：把识别画面(带状态标注)存到 debug/ 目录，便于排查
.\.venv\Scripts\python.exe app.py --debug
```

也可以在资源管理器里**双击** `启动计时助手.bat` / `校准.bat`。

## 快捷键与悬浮窗（托盘图标控制）

| 控制方式 | 作用 |
|---|---|
| **右下角托盘图标 右键** | 悬浮窗平时是**鼠标穿透**的（不挡游戏任何点击）。右键托盘：锁定/解锁悬浮窗、自动回锁开关、**改手动计时键**、退出 |
| `Ctrl+Alt+L` | 悬浮窗 锁定/解锁（备用，与托盘同效） |
| `Ctrl+Alt+Q` | 退出程序 |
| 鼠标**侧键** `XBUTTON2`(默认) | 手动开始一次 60s 计时（自动识别的兜底，启动一个空闲计时器） |

交互说明：

- **锁定（默认）= 整窗鼠标穿透**：数字栏完全透传点击给游戏，不显示任何按钮；控制全在托盘/热键。
- **解锁（拖动微调）**：从托盘或按 `Ctrl+Alt+L` 解锁 → 穿透关闭，可点住悬浮窗任意位置拖动微调；此时悬浮窗顶部会**出现一个锁图标**，点它即可重新锁定（或再用托盘/热键）。
- 解锁后若 `overlay.auto_relock_s` 秒（默认 20）内没有拖动，会自动回到锁定(穿透)，避免忘记锁而挡游戏。
- 位置在拖动结束/锁定时自动写入 `config.json`，下次启动回到原位。
- **4 个计时器 = 4 名逃生者，一一对应、互不抢占**；手动兜底键启动一个空闲计时器，4 槽全忙则忽略。
- **自动识别时悬浮窗自动贴齐头像列左侧**：每行数字中心对准对应头像中心（行距=头像间距，无需手动逐行对齐）；数字**保留一位小数**，半透明背景上下缘基本贴合整列头像。

## 分辨率支持（1080p / 2K / 4K）

无需按分辨率改配置，本工具的设计本身就是分辨率无关的：

- **识别**：头像框存的是**归一化坐标**，抓屏按游戏窗口实时取，分类器把每个裁剪统一缩放到 24×24 → 检测不依赖分辨率；
- **悬浮窗**：按“归一化坐标 × 游戏窗口实时矩形”锚定，并把字号按窗口宽度等比放大 → 1080p/2K/4K 下数字都贴合在头像左侧（`overlay.font_px` 是 1080p 参考字号，默认 24）。

> 前提是 DBD 使用**同一宽高比（16:9）**。若改用带鱼屏等不同宽高比，头像相对位置可能变化：在该分辨率下重新跑一次 `app.py --calibrate` 即可（坐标覆盖更新），其余无需改动。

## 校准（推荐，提升自动识别准确率）

`app.py --calibrate` 打开校准窗口，画面上是 DBD 实况（底部 HUD）：

1. **框选 4 个头像**：用鼠标在底部 4 个幸存者头像上各拖一个框（最多 4 个，多画顶掉最早）。
2. **先给每个框拍【记为正常】**：点中某个框（变红）→ 点【记为正常】（保存该槽位的"正常"基线，程序用它与后续状态图做差，从而**去掉角色脸和地图背景、只留下状态图标**）。
3. **出现状态时拍【记为上钩 / 记为倒地】**：等有人**上钩**时，点中该框 →【记为上钩】；有人**倒地**时，点中该框 →【记为倒地】。多拍几张更稳。

   | 按钮 | 何时按 | 存的内容 | 作用 |
   |---|---|---|---|
   | 记为正常 | 该框是正常走动状态 | 该槽原图（每槽一张基线） | 作为"减数"，把脸/背景减掉 |
   | **记为上钩** | 该框里的人正挂在钩上 | **差异图**(状态图−正常图) | 让程序认得"上钩图标"→ 上钩→恢复 才触发计时 |
   | **记为倒地** | 该框里的人正倒地(濒死) | **差异图**(状态图−正常图) | 让程序认得"倒地图标"→ 倒地→恢复 不会误触发 |

   - 建议在**自定对局（机器人局）**里操作：开局的健康机器人正好用来逐个拍"正常"；挂上一台拍"上钩"；砍倒一台(别挂)拍"倒地"。
   - 画面可 **“暂停/继续”** 方便精确指认。
4. 点 **“保存并退出”**。

校准结果存于 `config.json`（归一化坐标）与 `templates/`：`alive/`(每槽正常基线) + `hooked_diff/`、`downed_diff/`(差异模板)。**模板在程序启动时加载**，校准后需**重启** `启动计时助手.bat` 才会生效（日志出现 `hooked模板N张/downed模板M张` 即成功）。

> 没做模板校准也能用：此时走 `simple` 模式，**任何“偏离→恢复”都当作下钩**，代价是“倒地后被人拉起/自起”会误触发一次计时。做完 正常+上钩/倒地 模板后，倒地恢复不会再误触发。

## 检测原理与已知局限

- 每个头像槽维护一张**自适应“正常存活参考”**（跟随该角色外观缓慢学习，无需为每个角色单独拍照）。
- 槽位画面长期偏离参考 => 认为进入某种状态；分类"上钩 vs 倒地"时用**差异图**（当前图 − 该槽正常图）比对模板：差异图已去掉静止的脸与地图背景，只保留状态图标，可跨角色/跨地图复用。
- 被识别为“倒地”后恢复（倒地拉起/自起）**不**计时；其余偏离（上钩、或模板未完全认出的变化）恢复到正常即判定为一次被救下钩并计时（**宁可多报、不漏报**）。
- 三挂牺牲（死亡）不会恢复到“正常”，因此**不会**误触发。
- 已知局限（已尽量在代码/文档里交代）：
  1. 本机无法直接验证 DBD 像素，**默认无框**，务必先校准；
  2. 若程序启动时对方**已经挂在钩上/已倒地**，可能漏掉或需等自动重设基线；
  3. 没拍模板时(简单模式)倒地拉起会误报；拍了 上钩/倒地 差异模板则不会；
  4. 多显示器时目前按**主显示器/窗口所在区域**抓取，若有异常把 DBD 放主屏跑。
  5. 为避免“窗口被遮挡时把聊天/桌面误判成下钩”，程序**只在 DBD 处于前台时**做画面识别（切出游戏会自动暂停，切回自动恢复并重建基线）。如确需后台识别，可把 `config.json` 的 `detect.require_foreground` 改为 `false`。
  6. 为避免把“头像区的秒级动画/高亮抖动”误判成下钩：画面需**持续偏离超过 `detect.min_event_s`(默认 2.5 秒)** 才认为进入状态；短暂闪烁/抖动会被忽略（代价：极短的状态变化可能漏报）。若仍有抖动误报可调大该值。
- 排查：`--debug` 运行一段时间后把 `debug/dbg_*.png` 发给我即可针对性调参（阈值在 `config.json` 的 `detect` 段）。

## 图标识别方案（默认引擎）

不再依赖“每局随机的角色脸”做整脸比对，而是直接识别**固定的状态画面**（钩上/献祭）：状态机只认“钩上 → 离开：不是献祭才计时”，可天然过滤倒地拉起等误报。

采集流程：

1. **抓帧**：玩游戏时让 DBD 保持前台，运行 `python capture_frames.py --interval 4`，画面存到 `samples/raw/`。
2. **标注**：结束后运行 `python label_icons.py`，逐帧用数字键给 4 人标状态：`1=上钩 2=献祭 3=正常`；按空格=整帧全正常（最常见的帧一键归档），自动存入 `templates/icons/{normal,hooked,sacrificed}/`。
3. **训练**：`python train_icon_clf.py` 生成 `templates/icon_model.npz`。
4. **接入**：重启主程序即自动加载模型（未训练前分类器为占位、不触发）。

**样本量建议**：`normal` 50+、`hooked` 20+、`sacrificed` 20+。因图标/状态画面固定，每类几十张就够用；覆盖不同角色与地图会更稳。机器人局最易采集：上钩时段与三挂献祭时段内的每一帧都能标。

```
  timers.py             4 槽 60s 计时内核（槽=幸存者一一对应）

  calibration.py        校准界面
  keycapture.py         按键重绑对话框
```

# DBD 下钩计时助手

黎明杀机（Dead by Daylight）杀手端下钩计时助手：当人类被救下钩时开始 60 秒正计时，用颜色区分当前处于哪个保护窗口；4 个计时器与 4 名逃生者一一对应，悬浮在游戏画面旁。

> ⚠️ **使用须知**
> - 本工具**只识别你自己的屏幕画面**，不读取/写入游戏内存、不注入、不修改游戏文件。
> - “自动提示下钩时间”会给杀手提供游戏故意隐藏的信息，属公平性灰色地带；请了解机制、自用学习，账号风险自负。介意者只用“手动计时”即可（相当于普通秒表）。
> - 建议 DBD 用**无边框窗口**模式运行（本工具按此设计）。

## 计时规则与颜色

数字从 0 正数到 60（保留一位小数，如 `12.3`）；某人被下钩只启/重启他自己的计时器，互不抢占。

| 数字颜色 | 阶段 | 含义 |
|---|---|---|
| 🟡 黄色 | 0 ~ 10 秒 | **下钩保护**（耐力+加速）生效中 |
| ⚪ 白色 | 10 ~ 60 秒 | 只剩**果断反击(DS)** 可用 |
| 消失 | 数到 60 | 计时结束，该行清空 |

## 安装（一次性，源码运行）

在项目根目录（仓库克隆/解压到的文件夹）打开 PowerShell 执行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 运行（源码）

```powershell
.\.venv\Scripts\python.exe app.py             # 正常使用（自动识别 + 手动1~4键精确计时）
.\.venv\Scripts\python.exe app.py --calibrate # 校准头像框
.\.venv\Scripts\python.exe app.py --demo      # 无需游戏，演示悬浮窗效果
.\.venv\Scripts\python.exe app.py --debug     # 调试：把识别画面存到 debug/（仅排查用）
```

也可以直接双击 **`启动计时助手.bat`** 正常启动。

## 托盘图标 · 快捷键 · 悬浮窗

| 控制方式 | 作用 |
|---|---|
| **托盘图标右键** | 锁定/解锁悬浮窗、**校准头像框…**、**快捷键设置…**、自动回锁开关、退出 |
| **快捷键设置页** | 自定义热键：`手动1~4` / `锁定-解锁` / `退出`，保存即生效（写回 `config.json`） |
| `F1`~`F4`（默认，可改） | **手动精确计时 1~4 号逃生者**：看到几号被下钩就按对应键，只启/重启那位的计时器 |
| `Ctrl+Alt+L`（默认，可改） | 悬浮窗 锁定 / 解锁 |
| `Ctrl+Alt+Q`（默认，可改） | 退出程序 |

> 设置页会校验：各功能不能设成同一个键；“退出”必须带修饰键，防止误触退出。

悬浮窗交互：

- **悬浮窗只在进入 DBD（检测到游戏窗口）后自动出现**；没开 DBD 时不显示（托盘常驻并提示一次），进入游戏自动贴齐，退出游戏自动收起。
- **锁定（默认）= 整窗鼠标穿透**：完全不挡游戏点击，也不显示任何按钮。
- **解锁（拖动微调）**：穿透关闭、可拖动；顶部出现 🔓 锁图标，点它立即重新锁定（也可用托盘/热键）。
- 解锁后 `overlay.auto_relock_s`（默认 20）秒内没拖动，会自动回到锁定。
- 拖动结束/锁定时，位置写回 `config.json`，下次启动回到原位。
- 自动识别时，4 行数字自动**贴齐头像列左侧**（每行中心对准对应头像中心，无需逐行手动对齐），背景为半透明深色。

## 校准头像框

首次使用 / 换分辨率时做一次：**启动后若未校准，程序会自动弹窗引导**；也可随时托盘右键 **校准头像框…**，或在源码里跑 `app.py --calibrate`。

1. 在左侧幸存者状态列上，把 4 个状态图标各拖一个框（最多 4 个，多画顶掉最早）；
2. 点 **“保存并退出”**——程序会**自动切回 DBD 前台**，识别即刻恢复，无需手动点游戏窗口。

校准只把 4 个框的**归一化坐标**写入 `config.json` 的 `hud.boxes`。识别不依赖“正常/上钩/倒地”模板，所以换角色、换地图、同宽高比下换 1080p/2K/4K 都**无需重新校准**。

## 分辨率支持

识别与显示都与分辨率无关：头像框存归一化坐标、抓屏按窗口实时换算，分类器把每个裁剪统一缩放到 24×24；悬浮窗按“归一化坐标 × 窗口矩形”锚定，字号随窗口宽度等比放大（`overlay.font_px` 为 1080p 参考字号，默认 24）。前提是 DBD 保持 **16:9**；改带鱼屏等不同宽高比后重跑一次校准即可。

## 工作原理与已知局限

- 识别方式：对每个头像框裁剪，缩放 24×24 灰度后，用原型分类器按「判别区 mask」判断 `hooked`(钩上)/`sacrificed`(献祭)；状态机只在“钩上 → 离开且非献祭”时触发一次下钩计时。
- 钩上判定用更高独立阈值 `detect.icon_hook_thr`（默认 0.65），避免“被救后的受伤人脸”对钩形 ~0.55~0.60 的误相关、被误判成一直钩上而漏报。
- 已知局限：
  1. 自动识别需**先校准框**，且源码运行还需 `templates/icon_model.npz`（训练产物）存在；未校准/无模型时可用 **手动1~4 键** 精确计时；
  2. 启动时若某人**已在钩上/已死**，可能漏掉该次或需等其状态变化；
  3. 程序**只在 DBD 处于前台**时识别（`detect.require_foreground`），被遮挡/最小化时暂停，切回自动恢复，避免把桌面/聊天误判成下钩；
  4. 多显示器按游戏窗口所在区域抓取，异常时把 DBD 放主屏。

> **隐私**：正常使用不会向磁盘写任何截图，也不会创建 `debug\`；只有显式调试（`--debug` 或把 `config.json` 的 `detect.debug_frames` 设为 `true`）才惰性创建并写带标注帧，供排查（把 `debug\dbg_icon_*.png` 与 `运行日志.log` 发回即可定位）。

## 重训模型（仅维护者）

识别的是固定状态图标，通常无需重训；仅当想用最新对局渲染提升分类余量时才需要：

1. **抓帧**：让 DBD 前台运行 `python capture_frames.py --interval 4` → `samples/raw/`；
2. **标注**：`python label_icons.py`，逐槽按 `1=上钩 2=献祭 3=正常`，空格=整帧全正常 → `templates/icons/{normal,hooked,sacrificed}/`；
3. **训练**：`python train_icon_clf.py` 生成 `templates/icon_model.npz`，重启主程序即加载。

样本量建议：`normal` 50+、`hooked` 20+、`sacrificed` 20+（机器人局最易采集）。

## 目录结构

```
app.py                  入口（正常/--calibrate/--demo/--debug）
启动计时助手.bat         双击启动（正常模式）
requirements.txt        依赖
config.json             运行时生成的配置（框、热键、显示设置，不入库）
templates/              图标模型 icon_model.npz 与训练样本（不入库）
samples/                训练数据收集目录（不入库）
debug/                  调试帧（仅显式调试才生成，不入库）
capture_frames.py       抓帧（训练数据采集，维护用）
label_icons.py          标注（训练数据采集，维护用）
train_icon_clf.py       训练图标模型（维护用）
tests_smoke.py          冒烟测试
dbdtimer/
  config.py             配置读写（含路径/模型解出）
  timers.py             4 槽 60s 计时内核
  overlay.py            透明悬浮窗（锚定、字号自适应、锁定穿透）
  gamewindow.py         定位 DBD 窗口（纯 Win32）
  capture.py            截屏（dxcam → mss 降级）
  iconclf.py            图标分类器（原型匹配，钩上/献祭独立阈值）
  iconstate.py          下钩状态机（钩上→离开判定）
  iconengine.py         图标识别引擎
  hotkey.py             全局热键轮询
  calibration.py        校准界面（框选 4 个头像框）
  keycapture.py         快捷键设置/按键捕获
```
